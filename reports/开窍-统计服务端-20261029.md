# 开窍匿名统计服务端本地验收（2026-10-29）

分支 `feat/metrics-backend`，基于 main@896f3ae。仅本地实现、构建与验证；客户端默认关闭，没有线上部署、API 调用、数据集或绑定操作。提交作者均为 Codex <codex@localhost>。

## 设计与理由

采用 Pages Functions，函数仅匹配 `/e`，纯模块 `handleEvent(request, env)` 集中校验。按方法、同源和 host、媒体类型、512 字节流上限、严格 JSON 协议、绑定存在性顺序处理；所有响应空 body，显式 no-store、nosniff、no-referrer。非 POST 包括 OPTIONS 返回 405/Allow，无 CORS；写入异常吞掉，204 不保证持久化成功。

每次最多写一个点：indexes=[event]，blobs=[event, grade 或 none, prod/preview/dev]，doubles=[1]。服务端不读取 IP、UA、Cookie、Referer、request.cf 或标识；不记录日志、不重试。源码及 bundle 用禁用词断言约束。AE 自带 timestamp，处理模块不提交自定义时间戳。

[Pages 路由](https://developers.cloudflare.com/pages/functions/routing/)支持用 `_routes.json` 限定函数调用，故只 include `/e`。函数响应不套用静态 [headers](https://developers.cloudflare.com/pages/configuration/headers/) / [redirects](https://developers.cloudflare.com/pages/configuration/redirects/)，因此模块自行返回安全头，静态路径保持原行为。本地实测四类静态路径与旧中文入口均通过。

[AE 绑定](https://developers.cloudflare.com/pages/functions/bindings/#analytics-engine)通过项目面板/API 配置 `METRICS` → `kaiqiao_metrics`；本轮不做配置。AE 本地不可用，开发验证明确预期无绑定 503。不新建 wrangler 配置，避免接管项目设置。

按已定 wrangler 3.114 行为，functions 从工作目录发现：入口放 `site/functions/e.js`，从 site/ 部署才带函数，根目录普通部署仍纯静态。全局 wrangler 3.114.17 的本地 functions build 已验证生成路由仅 `/e`。

## 风险与限制

- 无速率限制；Origin/Fetch Metadata 是浏览器约束，可被非浏览器伪造。count 固定 1 和体积限制不能阻止反复刷量。
- Cloudflare 边缘网络本身可见 IP 等连接信息，本模块不读取、不存储、不记录这些字段；不宣称网络层不可见。
- [Functions 免费计划](https://developers.cloudflare.com/pages/functions/pricing/)与 Workers 共享 100,000 请求/天，UTC 午夜重置。应确认 [fail open](https://developers.cloudflare.com/pages/functions/routing/) 使超额后继续静态服务；配置 fail closed 会返回错误页。本轮未检查或修改线上实际设置，超额会丢统计。
- [AE SQL API](https://developers.cloudflare.com/analytics/analytics-engine/sql-api/)按索引采样，写入/读取都可能采样。查询必须加权；[保留期三个月](https://developers.cloudflare.com/analytics/analytics-engine/limits/)。事件计数不等于独立人数、真实学习效果或完整精确审计。
- 写入抛错返回 204，不重试、不记日志，故成功 HTTP 响应不保证点已持久化。无绑定则明确 503。
- 普通 build 暂时移除离线 HTML 并改写 SW，release 会重建恢复；最终 release 已确认无产物差异。Vite 原有超过 500 kB chunk 警告保留，没有为本任务更改应用拆包。

## 小杨复核修正（2026-10-29）

- **同源判断放宽一处、仍严格**：Fetch 规范规定 `referrerPolicy:'no-referrer'` 的非 GET 请求序列化 Origin 为 `null`；客户端正是这样发的。Chromium 实测仍发真实 Origin，但遵循规范的浏览器会发 `Origin: null`，原实现会把这些真实请求全部 403。改为：Origin 非 `null` 时必须等于请求源；Origin 缺失或为 `null` 时必须有 `Sec-Fetch-Site: same-origin`；任何非 same-origin 的 Sec-Fetch-Site 一律 403。新增 7 条单测（统计单测 51 项）。客户端代码未改。
- **真实浏览器端到端**：`check-metrics-pagesdev.mjs` 新增 Chromium 检查：默认首页零 `/e` 请求；页面内用已发布的 `metrics.js` 发 `grade_select`/3，响应 503（= 通过全部校验、仅缺本地 AE 绑定），请求体与协议一致、无 Cookie/Referer；另加未知路径仍由静态 404.html 返回 404。共 11 项 PASS。
