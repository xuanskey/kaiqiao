## 1. 计费与取整（唯一口径）

| 项 | 规则 |
|---|---|
| 单位 | 1 点 = 1 分 = 0.01 元 |
| 成本 | DeepSeek 官方人民币价（deepseek-flash）为成本 |
| 倍率 | 对用户 **1:4**：`billFen = costFen × 4` |
| 取整顺序 | **先算 costFen（向上取整到分，最低 1 分）→ 再 ×4** |
| 最小扣费 | 有用量即至少 costFen=1 → billFen=4 |
| 空答/失败 | 上游失败、空答案 → **不扣点** |
| 余额不足 | 调用前拒答，不欠费，不透支 |

官方费率（元/百万 tokens）：

| | 空闲 | 高峰 |
|---|---|---|
| 输入·缓存命中 | 0.02 | 0.04 |
| 输入·缓存未命中 | 1 | 2 |
| 输出 | 4 | 8 |

高峰：北京时间周一至周五 9:00–12:00、14:00–18:00；法定节假日全天空闲。

公式：
```
units   = (prompt − cached)×100 + cached×2 + completion×400   // 分/百万 tokens
scaled  = units × (高峰 ? 2 : 1)
costFen = max(1, ceil(scaled / 1_000_000))
billFen = costFen × 4
```

样例（手算，未调 API）：

| 场景 | costFen | billFen |
|---|---|---|
| 小额调用（如官方 0.0012 元） | 1 | **4** |
| 空闲 1000 输入未命中 + 500 输出：units=100000+200000=300000 → 0.3 分 | 1 | 4 |
| 空闲 1,000,000 输出 = 4 元 | 400 | 1600 |
| 高峰 1,000,000 输出 = 8 元 | 800 | 3200 |

**作废**：旧文「再 ×4」「若 billFen<1 按 1 点起扣」等先乘后取整的说法。以本节为准。

对账：每笔账本同时记 `costFen`、`billFen`、usage、费率档（高峰/空闲）。

## 2. 充值金额与点数

| 规则 | 定法 |
|---|---|
| 金额 | **不限档位**；用户自填，**只限正整数元**（1、2、3…；不要小数） |
| 换算 | 1 元 = 100 点（1 点 = 0.01 元） |
| 最低 | **1 元**（取消原「最低 5 元 / 固定 5·10·20·50」） |
| 上限 | 单笔建议 ≤ 500 元（防误触；可调，另定） |
| 折扣 | 不送点、不打折 |

- **1:4 只作用于扣费，不作用于充值**（充 N 元就是 N×100 点）。
- 变更（2026-10-27）：杨哥定「充值不限金额、只限整数」，替换固定档位。

## 3. 支付自动入账状态机（本期只规格，不接支付）

```
CREATED(下单, 填整数元金额) → PENDING(待付, 生成 orderId)
  → 回调到达 → 验签 → 核对实付金额 == 下单金额（整数元）
      ├ 通过 → PAID → 幂等入账(同 orderId 只入一次) → CREDITED
      ├ 验签失败 → 拒收, 记日志, 不入账
      └ 金额不符 → ANOMALY, 不入账, 入人工台账
  PENDING 超时 → EXPIRED（可主动查单）
对账：每日拉支付侧账单 ↔ 账本；漏单 → 主动查单补入（幂等）；仍异常 → 运维 topup 兜底（须杨哥批）
```

- 渠道：微信/支付宝。**对接另批。**
- 充值码：仅运维兜底（补单/测试），不是用户主路径。

## 4. 退款规则

- 未消耗可退；已消耗不退。
- 退款额 = 未用点数对应的**实付金额**（1 点 = 0.01 元实付），按原充值订单逐单冲回；**不按余额÷4 算**。
- 多笔充值：按先进先出扣点，退款从最近未消耗订单回退（默认，见末尾歧义）。
- 流程：用户申请 → 杨哥逐笔确认 → 原路退回（支付侧退款）→ 账本记负向流水并关联原单。

申请需提供：账户标识、原订单号（或支付时间+金额）、申请退款点数、联系方式、原因（可选）。
