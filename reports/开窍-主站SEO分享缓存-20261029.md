## 第 5 步：缓存（通过）

不再使用 `/assets/*` 的广泛缓存规则，避免其与新图精确规则同时匹配时合并 Cache-Control。最终 `_headers` 的所有规则：

| 路径 | Header / 用意 |
| --- | --- |
| `/*` | 仅 `X-Content-Type-Options: nosniff`、`Referrer-Policy: strict-origin-when-cross-origin`；不设置 Cache-Control |
| `/app/assets/*` | `public, max-age=31536000, immutable`；保留构建哈希资源长缓存 |
| `/assets/og-cover-20261029.jpg` | `public, max-age=31536000, immutable`；明确带日期版本的分享图 |
| `/assets/brand.svg` | `public, max-age=3600`；同名可替换的品牌文件 |
| `/assets/favicon.svg` | `public, max-age=3600`；同名可替换的图标 |
| `/assets/lantern.svg` | `public, max-age=3600`；同名可替换的插图 |
| `/assets/kaiqiao-promo-poster.jpg` | `public, max-age=3600`；未版本化海报 |
| `/assets/kaiqiao-promo.mp4` | `public, max-age=3600`；未版本化视频 |
| `/styles.css` | `no-cache`；query 版本不能用于 Pages 路径匹配，允许复用响应但须重新验证 |
| `/app.js` | `no-cache`；同上 |
| `/` | `no-cache`；首页（含 ?practice=1，匹配不看 query） |
| `/index.html` | `no-cache`；首页显式文件路径 |
| `/app/` | `no-cache`；内嵌应用入口 |
| `/app/index.html` | `no-cache`；应用显式文件路径 |
| `/app/sw.js` | `no-cache`；应用 service worker |
| `/sw-practice.js` | `no-cache`；练习导航 service worker |

取舍：不为首页 CSS/JS 引入文件复制与版本同步机制；保留原 query URL，通过 no-cache 确保更新。未版本化媒体缩短至一小时，新资源默认没有 immutable；要增加长缓存须使用新文件名并增加精确规则。版本图内容修改时必须更换版本文件名和引用。

`scripts/check-site-cache.mjs` 模拟路径匹配并收集所有匹配规则的 Cache-Control，断言每个目标路径恰好一个缓存值；确认所有 HTML/SW 为 no-cache、分享图长缓存、现有未版本化资源短缓存，并检查 app/assets 当前所有文件名包含哈希。运行通过，不依赖“后面覆盖前面”的假设。Cloudflare 线上实际响应未测试（按要求未部署）。

已检查 `scripts/sync-app-to-site.mjs`、`scripts/release.mjs`、Vite 配置：不重写主站 `_headers` 或主站 index.html；同步只替换 app 子目录。release 按入口 HTML 哈希生成 `kaiqiao-${version}` 并清理旧 `kaiqiao-*` 缓存，未修改此更新机制。
