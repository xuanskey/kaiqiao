## 1. 问题核实

在 v0.13.1 的生产构建上，用固定随机种子、独立数学参考答案和模拟 fetch 运行相同浏览器断言，得到 3 通过、31 失败。失败是测试场景数，不代表 31 个独立缺陷；包括新要求的主动取消控件尚不存在等情况。所有测试都保留正常失败退出码，没有跳过或反转断言。

| 编号 | 结论与复现证据 | 修复后验收 |
| --- | --- | --- |
| P1-01 | 已复现。输入 `123456` 后分别点「再难一点」「简单一点」「给我出一道题」，题干改变而输入仍为 `123456`。另发现「我没听懂」将 `4.8 ÷ 0.6` 换成 `13.2 ÷ 3`，旧输入也未清除。 | 明确换题清空输入/反馈；普通后续难度调整保留当前题与草稿。 |
| P1-02 | 已复现。错误反馈显示后点「给我出一道题」，`.quiz-feedback` 数量仍为 1，旧题遮住新题；选择题也未解锁。 | 新题立即可作答；课堂和每日活动记录不增加，原有正确率保留。 |
| P2-03 | 已复现。两次正确后仍显示标准题解析，但头部为「提高 · 本次 2/2」；两次错误则提前变为「简单 · 本次 0/2」。 | 反馈显示 `PracticeQ.level`，另行提示下一题难度；点下一题才采用新难度。 |
| P2-04 | 已复现旧回复覆盖：离线操作产生「换一种想法来讲。」后，释放延迟响应，消息变为「过期回答 A」。清密钥/禁用/改模型后请求也未取消。 | 取消传输并检查请求身份，迟到回复不能写回；旧请求结束不能清除新请求的 loading。 |

**需要区分的事实**：v0.13.1 正常网络失败、HTTP 503，以及遵守 AbortSignal 的 fetch 超时处理本来就通过。没有把它们报告为原有缺陷。额外测试故意让传输忽略 abort，以验证界面仍能结束等待。离开课堂后，React 不会把旧组件的 setter 写入新挂载课程；验证发现的是请求没有取消，并未声称复现了跨卸载的新课污染。

**同源问题**：同一 JavaScript 任务内连续派发两次 submit，v0.13.1 的持久化 attempts 为 2（预期 1）；现在加入同步提交锁。两次错误后的「同类再练」原本会降为简单题；现在明确保留原题难度、题型和教学分支。

## 2. 根因与方案

原 Quiz 的 `useMemo` 会随 `level` / `nonce` 重新生成题目，但 `draft`、`result`、`history` 各自独立。`result ? result.q : q` 只冻结了反馈题干，既不能处理主动换题，也没有冻结难度标签。仅用 `result` 检查重复提交，要等 React 完成本批状态更新才生效，重复事件可能重复执行持久化副作用。

改为小型纯 reducer 保存当前 `PracticeQ`、草稿、锁定结果、历史、题目序号与请求来源。只有显式换题事件创建题目；新题、清草稿、清反馈一次完成。来自旧题 ID 的提交/输入事件无效。普通 `nextLevel` 更新不生成题目。显式 nonce/课程变化在本组件渲染中协调，再提交子树，避免 effect 清理之前有一帧可交互的旧输入。`onRecord` 仅从提交事件调用，并由同步 ref 防重；reducer 和 effect 不写学习记录。

AI 原来把每次异步返回直接交给 `onReply`。现在每节课有独立请求域：离线操作同步取消并失效旧请求，面板在响应时再检查身份；卸载后旧请求不能更新 UI。超时/外部取消与完整请求（含响应体读取）竞争，即使传输层忽略取消也会结束 loading。配置变更和取消按钮使用同一路径。

## 6. 限制与未完成事项

- 未测试真实 iOS/Safari、Firefox/WebKit、辅助技术读屏器或真实 AI 服务。模拟取消不能保证远端服务停止计费，但可保证客户端不使用迟到结果。
- 单一固定知识题可能没有不同题干可生成（例如固定常识判断）。抽样有上限；同类/同难度优先，必要时复用该题内容并分配新 ID，输入与反馈仍重置。这不是沿用旧提交结果。
- 构建仍有原有的大 chunk 提示；本轮不扩大到无关拆包工作。
- `npm run check` 更新版本后曾抓到使用指南/下载说明标题仍旧，已更新源说明并重新全量通过，未放宽测试。
- 扩展全课程测试时曾误用可见文字“完整过程”作精确 accessible name；实际 aria-label 为“查看完整过程”。已修正选择器后重跑，没有削弱断言。
- GitHub 连接能够读取仓库，但创建 Git tree 返回 `403 Resource not accessible by integration`；本地 push 也因没有凭据失败。插件确认为已安装启用，问题属于连接/安装的 GitHub 写入授权，不是本地测试失败。需要维护者为当前 GitHub 连接补充该仓库的写入权限，之后才能推送、创建 PR 并核验 Actions。
