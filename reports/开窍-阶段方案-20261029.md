### 1.5 备份导入（由原方案改为已实施）

main 的旧导出是 `{app:"kaiqiao",format:1,exportedAt,data,extras?}`，原学情有导出/恢复入口；另路 patch 是 `{app:"kaiqiao",kind:"practice-backup",version:1,exportedAt,origin,data:{五键}}`。本次基于该 patch 实施，两种均可导入，旧 format:1 不要求新增 kind/version/origin；更早的无时间/无 extras 旧备份也兼容。

流程：选择文件 → 文件大小与 UTF-8 文本双重 2 MB 上限 → JSON/app/格式版本检查 → 主存档、课堂日志、活动、复习数据严格校验 → 页内预览年级/题数/错题与覆盖范围 → ConfirmAction 确认覆盖 → 调用既有 restore（写前把所有待写键的原始文本存入内存，写入并逐键读回；失败逐键回滚，成功才替换应用内存状态）。取消不写入，坏数据友好报错，未知键不写入；无 extras 的旧文件保留本机课堂与每日题数，无 review 的旧文件沿用现有错题重建复习逻辑。只导出五个练习键，不导出 AI 密钥/账号和损坏数据保护副本。

风险：浏览器在回滚时也持续拒绝写入，无法保证物理存储可恢复，应保留当前导出备份/原始存档；不承诺原子事务。此轮未改 restore 调度逻辑。旧格式有些字段原本可容错，本次导入损坏条目时明确拒绝，不静默抹除。现代格式仍正常导出，没有自动云同步。

工作量：导入兼容与回归约 0.5–1 人日/1–2 轮。验收：新格式与旧格式往返、旧格式坏数据、2 MB、取消不写、确认恢复、写失败五键回滚，无原生 dialog。现有单测与浏览器检查覆盖这些路径。需要杨哥：用真实的历史备份做脱敏之外的本人本机验收，不把备份上传给本项目或统计系统。

### 1.8 404 入口审计

Cloudflare Pages 无顶层 404 时默认 SPA 回落；有顶层 404 则未知路径返回自定义 404（[官方说明](https://developers.cloudflare.com/pages/configuration/serving-pages/)）。

| 路径/机制 | 审计结论 |
| --- | --- |
| `/`、`/?practice=1`、带 grade/lesson 参数 | 真实 index.html；查询参数不参与静态文件查找 |
| `/app/`、`/app/index.html` 与 assets/manifest/sw/offline | 真实文件；应用内部屏幕靠状态切换，不是 `/app/某屏幕` 路由 |
| `/app` | Pages 目录补斜杠，之后应用现有顶层脚本转回公共练习入口 |
| `/练习`、`/练习/` | `_redirects` 显式 301，先于 404；不依赖回落 |
| `sw-practice.js` | 只接管同源根路径且 practice=1 的文档导航，其余不干预 |
| `app/sw.js` | 作用域内已安装离线导航失败回退到缓存 index；不改变在线未知路径的 404；未改缓存机制 |
| `docs/`、离线包 | docs 是独立产物根目录，非主站 `/docs/` 路由；已知 README 下载与站内链接没有依赖主站 `/docs/*` 的导航；docs 内真实文件不受主站 404 文件影响 |
| 旧 kaiqiao 子域 | 属另一源/项目，历史迁移说明保留，不擅自设置重定向；本地主站 404 不改变该源 |
| 首页全部链接/锚点 | 链接检查均可达；没有未知路径作为功能入口 |
| 新 `/grade/1/`…`/grade/6/` | 新增物理目录，不命中现有 redirects，根 SW 不接管，无需修改既有路由 |

因此已添加 404，未触发修改 `_redirects` 的停止条件。验证服务器模拟显式重定向、目录补斜杠、真实文件、顶层 404 与没有 404 时的原 SPA 行为；未知 `/不存在的页`、`/abc/def` 为 404 且返回首页可用。部署后的边缘真实行为仍需获准上线后复核。
