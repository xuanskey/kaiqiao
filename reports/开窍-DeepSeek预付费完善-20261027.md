## 本轮修改与自审

1. 前端 `sanitizeReply` 对齐现有 Worker 的较严格规则：删除 script/style 内容、大小写 HTTP(S) 链接、HTML/代码块及指定字符，压缩空白为单空格，限制 400 字符。两端保持独立实现；只有测试同时导入两者进行契约比对，Worker 运行时代码不 import 前端。自备密钥回复也使用此前端函数，因此同样采用新的空白规范。
2. ask 对净化后空文本返回 `503 / invalid_upstream_response`，不扣点、不写账本，并释放锁；防止前端提示无有效回答、服务端却扣费。该行为仅定义 mock 账本，真实上游已经发生费用时的处理留待 C 期。
3. 并发测试通过显式 Promise 进入/释放信号保持 ask 未完成，确认同账户 topup 和 ask 均返回 `409 / request_pending`，期间读取余额无变化、另一账户可充值。测试具备 5 秒超时及 finally/清理钩子，不依赖 sleep。另测 topup 先进入再与 ask 交叉调度：同步充值先完成，ask 使用新余额，两者成功且各记一笔；不人为增加 await 制造反向 409。
4. 增加上游抛错、非法 usage、空回答、余额恰好扣完、失败后再提问等账本与锁释放断言；固定限流测试时钟，验证 59,999 毫秒仍拒绝、60,000 毫秒恢复。
5. 增加混合缓存、整分两侧、大数进位、零 usage 最低收费及非法数字测试。以独立 BigInt 商/余数算法核对既有 Number 整数算法，生产代码不引入 BigInt。
6. 每个 API 单测拦截全局 fetch 并断言调用数为零；upstream 测试控制并恢复环境变量，验证默认 mock 和多种非 `1` 配置均不联网，且约束常量符合固定规格。

自审确认：本轮运行时代码仅增加空回答扣费保护、对齐前端净化以及纠正计费注释；日历、价格、互斥算法与模型约束无需重写。净化结果仍必须以文本渲染，正则清理不是 HTML 安全解析器。

## 仍属 mock 的边界 / C 期待办

- **内存账本**：余额、账本、限流和互斥仅存在于当前进程的 Map/Set；重启丢失，不跨实例，没有生产持久化、幂等充值或退款流程。Durable Object / 生产账本留给 C 期。
- **无会话鉴权**：accountId 是客户端提供的标识，不代表经过认证的用户。topup 的测试管理员令牌不能替代登录和账户归属鉴权；不对公网开放。
- **无真实上游**：默认 upstream 只返回固定 fixture，mock 非 `1` 直接拒绝。代码层 upstream 注入仅用于本地测试，HTTP 请求不能配置它。没有真实 DeepSeek / 付费 API / 出站 fetch 调用。
- **未做最大费用预留**：当前固定 mock usage 可预检；返回后复验余额只保护本地账本，无法防止真实上游已经产生而无法扣回的费用。真上游最大费用预留、真实 usage/价格核对、超时与失败结算留给 C 期，不能直接把 fixture 替换成付费调用。
- 未引入真密钥测通、登录体系、微信/支付宝、生产账本或部署；未修改 PR #18、Capacitor、iOS/Android 壳、DNS、Cloudflare/wrangler 生产配置；未 push、merge。
